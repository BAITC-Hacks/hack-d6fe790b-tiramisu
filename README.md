# Tiramisu — подбор event-подрядчиков

Tiramisu помогает заказчику выбрать до трёх подрядчиков из уже известного каталога. Пользователь задаёт город, дату, формат мероприятия, категорию и бюджет; сервис исключает занятые и неподходящие профили и объясняет каждую рекомендацию конкретными условиями. Демо рассчитано на заказчика и жюри хакатона, которым важно проверить логику подбора вживую.

## Что реализовано

- Веб-форма принимает обязательные параметры: город, дату, тип мероприятия, категорию подрядчика и бюджет в тенге. Длительность и язык работы необязательны.
- API возвращает не более трёх карточек с именем, категорией, городом, ценой «от» и объяснением, опирающимся на бюджет, формат, язык, длительность и текст профиля.
- Занятый в выбранный день подрядчик не попадает в результаты. Площадки хранятся в том же каталоге и проходят те же проверки.
- Интерфейс отдельно показывает три результата: рекомендации найдены, категории нет в выбранном городе, есть профили категории, но ни один не прошёл условия.
- При результате менее трёх карточек интерфейс показывает количество найденных вариантов и причины отсева: занятость, бюджет, формат, язык или длительность.
- Порядок результатов детерминирован: семантическая оценка, затем цена, затем идентификатор профиля.
- Каждый профиль в текущем демо отмечен как синтетический.

## Как работает подбор

1. Браузер загружает из API допустимые города, категории, форматы, языки и диапазон дат.
2. После отправки формы сервер ищет профили выбранной категории в выбранном городе.
3. Для них последовательно проверяются занятость на дату, бюджет, формат, а при заполнении — язык и длительность.
4. Прошедшие фильтры ранжируются по близости текста профиля к типу мероприятия и категории. При доступном ключе OpenAI используются эмбеддинги; при недоступном ключе или ошибке API включается стабильное локальное сопоставление слов.
5. Сервер отдаёт до трёх карточек и проверяемое объяснение для каждой; веб-страница отображает его вместе с итоговым статусом.

## Технологии

- Python 3.10+ и стандартная библиотека: HTTP-сервер, JSONL-загрузка данных, валидация и логика рекомендаций.
- HTML, CSS и JavaScript без фронтенд-фреймворков.
- OpenAI Embeddings API с моделью `text-embedding-3-small` — опционально, через серверную переменную `OPENAI_API_KEY`.
- Локальный детерминированный лексический fallback, если ключ не задан или сервис эмбеддингов недоступен.

## Архитектура

```text
frontend/index.html + frontend/app.js
              │ HTTP
              ▼
backend/server.py ──► backend/data/profiles.jsonl
       │
       ├── фильтрация: город → категория → дата → бюджет → формат → язык/длительность
       └── ранжирование: OpenAI embeddings или локальный fallback
```

Один Python-сервер раздаёт веб-страницу и API. Данные загружаются из JSONL при старте. Запросы к OpenAI выполняются только на сервере; браузер не получает API-ключ.

## Установка и запуск

Требуется Python 3.10 или новее. Дополнительные пакеты устанавливать не нужно.

```powershell
git clone https://github.com/BAITC-Hacks/hack-d6fe790b-tiramisu.git
cd hack-d6fe790b-tiramisu
python backend/server.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). По умолчанию сервер слушает только локальный адрес и порт `8000`.

Чтобы подключить семантическое ранжирование OpenAI, до запуска задайте ключ:

```powershell
$env:OPENAI_API_KEY = "ваш_ключ"
python backend/server.py
```

Без ключа сервис остаётся работоспособным: он выводит рекомендации с локальным fallback и отмечает этот режим в интерфейсе. Порт можно изменить переменной `PORT`, например `$env:PORT = "8080"`.

## Как проверить решение

Проверку можно выполнить в интерфейсе либо отправкой `POST /api/recommendations`. Дата во всех запросах должна находиться в диапазоне `2026-09-23` — `2026-12-31`.

| Сценарий | Параметры формы | Ожидаемый результат |
| --- | --- | --- |
| Плотная категория и ранжирование | Алматы, `2026-10-18`, юбилей, Ведущий, `350000 ₸`, русский, 5 ч | Три из нескольких подходящих ведущих. Повторите запрос: порядок будет тем же; статус также сообщает, сколько профилей занято именно `2026-10-18`. |
| Редкая категория | Алматы, `2026-11-01`, юбилей, Флорист, `250000 ₸`, русский | Три карточки флористов из редкой категории; объяснения различаются фактами из описаний профилей. |
| Пустая выдача из-за условий | Алматы, `2026-11-14`, свадьба, Ведущий, `300000 ₸`, русский | Статус «кандидаты есть, но условиям не соответствует ни один»: один ведущий занят на дату, другой не берёт свадебный формат. |

Для проверки изменения выдачи по датам повторите первый запрос с датой `2026-11-14`: часть доступных в другую дату ведущих занята, а интерфейс явно укажет дату и количество исключённых из-за занятости профилей. Для проверки отсутствующей категории выберите город `Зарубежье` и категорию `Кейтеринг`: появится отдельный статус, что такой категории в городе нет.

Тот же запрос можно повторить через PowerShell:

```powershell
$body = @{ city = "Алматы"; date = "2026-11-01"; event_type = "юбилей"; category = "Ведущий"; budget_kzt = 300000; duration_hours = 5; language = "русский" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/recommendations -ContentType "application/json" -Body $body
```

## Данные и интеграции

Текущий файл [`backend/data/profiles.jsonl`](backend/data/profiles.jsonl) содержит 31 демонстрационный профиль. Все они синтетические (`synthetic: true`); исходный хакатонный датасет в репозитории отсутствует. В набор добавлены профили для воспроизводимой демонстрации плотной категории «Ведущий» и редкой категории «Флорист». Записи включают категорию, город, цену, форматы, языки, максимальную длительность, занятые даты и описание.

Единственная внешняя интеграция — OpenAI Embeddings API. Она необязательна: при ошибке сети, отсутствии ключа или некорректном ответе сервис переключается на локальную оценку текста без прекращения работы.

API:

- `GET /api/options` — допустимые значения формы и границы календаря.
- `POST /api/recommendations` — подбор по `city`, `date`, `event_type`, `category`, `budget_kzt`; дополнительно принимает `duration_hours` и `language`.
- Поле `outcome` принимает `recommended`, `no_category_in_city` или `no_eligible_candidates`.

## Ограничения

- Развёрнутой публичной версии в репозитории нет; демо запускается локально по адресу `http://127.0.0.1:8000`.
- Каталог демонстрационный: 31 синтетический профиль. В нём есть 15 ведущих и 3 флориста для live-проверки, но отсутствуют реальные профили и полный исходный набор из 66 записей.
- В проекте нет бронирования, заявок, уведомлений подрядчикам и проверки реальной доступности после подбора.
- Эмбеддинги кэшируются только в памяти процесса. После перезапуска сервера кэш сбрасывается.
- Цена интерпретируется как цена «от» за событие, как она хранится в демонстрационных данных; для кейтеринга один профиль прямо указывает цену на гостя в описании.
