# Tiramisu — подбор event-подрядчиков

Tiramisu помогает заказчику выбрать до трёх подрядчиков из уже известного каталога. Пользователь задаёт город, дату, формат мероприятия, категорию и бюджет; сервис исключает занятые и неподходящие профили и объясняет каждую рекомендацию конкретными условиями. Демо рассчитано на заказчика и жюри хакатона, которым важно проверить логику подбора вживую.

## Что реализовано

- Веб-форма принимает обязательные параметры: город, дату, тип мероприятия, категорию подрядчика и бюджет в тенге. Длительность и язык работы необязательны.
- API возвращает не более трёх карточек с именем, категорией, городом, ценой «от» и объяснением, которое опирается на бюджет, формат, язык, длительность и текст профиля.
- Занятый в выбранный день подрядчик не попадает в результаты. Площадки хранятся в том же каталоге и проходят те же проверки.
- Интерфейс отдельно показывает три результата: рекомендации найдены, категории нет в выбранном городе, есть профили категории, но ни один не прошёл условия.
- При результате менее трёх карточек интерфейс показывает число найденных вариантов и причины отсева: занятость, бюджет, формат, язык или длительность.
- Порядок результатов детерминирован: семантическая оценка, затем цена, затем идентификатор профиля.
- У синтетических профилей есть заметная метка в карточке; исходные записи не меняются при добавлении синтетических.

## Как работает подбор

1. Браузер загружает из API допустимые города, категории, форматы, языки и диапазон дат.
2. После отправки формы сервер ищет профили выбранной категории в выбранном городе.
3. Для них последовательно проверяются занятость на дату, бюджет, формат, а при заполнении — язык и длительность.
4. Прошедшие фильтры ранжируются по близости текста профиля к типу мероприятия и категории. При доступном ключе OpenAI используются эмбеддинги; при недоступном ключе или ошибке API включается стабильное локальное сопоставление слов.
5. Сервер отдаёт до трёх карточек, число исключённых из-за занятости на выбранную дату и проверяемое объяснение для каждой; веб-страница отображает их вместе с итоговым статусом.

## Технологии

- Python 3.10+ и стандартная библиотека: HTTP-сервер, JSONL-загрузка данных, валидация и логика рекомендаций.
- HTML, CSS и JavaScript без фронтенд-фреймворков.
- OpenAI Embeddings API с моделью `text-embedding-3-small` — опционально, через серверную переменную `OPENAI_API_KEY`.
- Локальный детерминированный лексический fallback, если ключ не задан или сервис эмбеддингов недоступен.

## Архитектура

```text
frontend/index.html + frontend/app.js
              │ HTTP
              ▼
backend/server.py
              │
              ▼
backend/recommendation_service.py
      ├── загрузка и валидация JSONL
      ├── фильтрация: город → категория → дата → бюджет → формат → язык/длительность
      ├── ранжирование: OpenAI embeddings или локальный fallback
      └── объяснения из проверяемых данных профиля
              │
              ▼
backend/data/hackathon-dataset-anonymized.jsonl  ← основной каталог, когда добавлен
backend/data/synthetic-additions.jsonl           ← необязательные дополнения
backend/data/profiles.jsonl                      ← текущий fallback для демо
```

`hackathon-dataset-anonymized.jsonl` имеет приоритет: если файл присутствует, сервис загружает его и при наличии добавляет записи из `synthetic-additions.jsonl`. Эти дополнения не редактируют исходные строки и обязаны иметь `synthetic: true`.

Пока исходный файл не добавлен в репозиторий, сервер использует `profiles.jsonl`. Это текущий синтетический демонстрационный каталог, поэтому примеры ниже проверены именно на нём. После добавления исходного датасета нужно заново выбрать, проверить и обновить демонстрационные запросы.

## Установка и запуск

Требуется Python 3.10 или новее. Дополнительные пакеты устанавливать не нужно.

```powershell
git clone https://github.com/BAITC-Hacks/hack-d6fe790b-tiramisu.git
cd hack-d6fe790b-tiramisu
python backend/server.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). По умолчанию сервер слушает только локальный адрес и порт `8000`.

Чтобы подключить семантическое ранжирование OpenAI, до запуска задайте ключ:

```powershell
$env:OPENAI_API_KEY = "ваш_ключ"
python backend/server.py
```

Без ключа сервис остаётся работоспособным: он выводит рекомендации с локальным fallback и отмечает этот режим в ответе API. Порт можно изменить переменной `PORT`, например `$env:PORT = "8080"`.

## Как проверить решение

Проверку можно выполнить в интерфейсе либо отправкой `POST /api/recommendations`. Для текущего fallback-каталога дата во всех запросах должна находиться в диапазоне `2026-09-23` — `2026-12-31`.

| Сценарий | Параметры формы | Ожидаемый результат |
| --- | --- | --- |
| Плотная категория и ранжирование | Алматы, `2026-10-18`, юбилей, Ведущий, `350000 ₸`, русский, 5 ч | Три карточки из шести подходящих ведущих. Повторите запрос: порядок карточек не меняется. |
| Редкая категория | Алматы, `2026-11-01`, юбилей, Флорист, `250000 ₸`, русский | Три карточки из трёх профилей категории; объяснения различаются фактами из описаний. |
| Пустая выдача из-за условий | Алматы, `2026-11-14`, свадьба, Ведущий, `100000 ₸`, русский | Статус «кандидаты есть, но условиям не соответствует ни один»: часть профилей занята на дату, остальные превышают бюджет. |

Для проверки влияния занятости повторите первый запрос с датой `2026-11-14`: часть доступных в другую дату ведущих занята, а интерфейс укажет выбранную дату и число исключённых из-за занятости профилей. Для проверки отсутствующей категории выберите город `Зарубежье` и категорию `Кейтеринг`: появится отдельный статус, что такой категории в городе нет.

Тот же запрос можно повторить через PowerShell:

```powershell
$body = @{ city = "Алматы"; date = "2026-10-18"; event_type = "юбилей"; category = "Ведущий"; budget_kzt = 350000; duration_hours = 5; language = "русский" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/recommendations -ContentType "application/json" -Body $body
```

## Данные и интеграции

Каталог загружается из JSONL и валидируется при старте: проверяются обязательные поля, их типы, цены, длительность и даты занятости. Выбор источника:

- `backend/data/hackathon-dataset-anonymized.jsonl` — исходный хакатонный каталог, когда файл добавлен в репозиторий.
- `backend/data/synthetic-additions.jsonl` — необязательные синтетические дополнения к исходному каталогу.
- `backend/data/profiles.jsonl` — fallback, если исходный каталог отсутствует.

Сейчас в репозитории есть только fallback из 31 синтетического профиля (`synthetic: true`). Он нужен, чтобы приложение можно было запустить и проверить до загрузки исходных 66 записей. После появления исходного файла он станет основным каталогом, а сценарии раздела «Как проверить решение» должны быть регенерированы и подтверждены тестами.

Единственная внешняя интеграция — OpenAI Embeddings API. Она необязательна: при ошибке сети, отсутствии ключа или некорректном ответе сервис переключается на локальную оценку текста без прекращения работы.

API:

- `GET /api/options` — допустимые значения формы и границы календаря.
- `POST /api/recommendations` — подбор по `city`, `date`, `event_type`, `category`, `budget_kzt`; дополнительно принимает `duration_hours` и `language`.
- Поле `outcome` принимает `recommended`, `no_category_in_city` или `no_eligible_candidates`.
- Ответ содержит `results`, `total_eligible`, `rejection_counts`, `availability_summary` и `degraded`.

## Ограничения

- Развёрнутой публичной версии в репозитории нет; демо запускается локально по адресу `http://127.0.0.1:8000`.
- Исходный датасет из 66 профилей пока не добавлен. Текущая демонстрация построена на 31 синтетическом профиле.
- В проекте нет бронирования, заявок, уведомлений подрядчикам и проверки реальной доступности после подбора.
- Эмбеддинги кэшируются только в памяти процесса. После перезапуска сервера кэш сбрасывается.
- Цена интерпретируется как цена «от» за событие, как она хранится в каталоге; для кейтеринга один fallback-профиль прямо указывает цену на гостя в описании.
